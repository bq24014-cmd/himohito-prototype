各区間について、現在の移動・接続・橋生成の処理で通過できる経路を確認した。ただし、チェックポイントの欠落を確認しており、「通しプレイで問題なし」とは判定できない。シーン遷移後の初期化にも要確認事項がある。

## 確認方法と限界

- Unity 6000.3.21f1 の隔離プロジェクトで、現在の保存シーンのコピーと現在のランタイムコードを使用。スクリプト参照は検証用 DLL の MonoScript へ変換した。
- 実際の PlayerMover、RopeController、RopePlatformBuilder、生成橋、物理判定を使い、入力相当の値と物理ステップで到達を検証した。トゲ、光の遮蔽、レールの判定も含めた。
- 到達テストではシーンのセットアップを明示実行し、区間ごとに位置・残量・進行状態を設定した。残量の連続計算は別テストで確認した。したがって、最初から最後まで状態を引き継いだ手操作の通しプレイではない。
- 画面操作ツールに接続できず、実画面での操作感・表示・音・連続プレイは未確認。
- 遷移テストは Play Mode で実際の LoadNextStage を呼び出したもの。宝箱への到達からクリア演出までの全操作を再現したものではない。

## 問題点

### 1. 本編第2区間のチェックポイントがない — 確認済み

保存シーンの `Main Landing 1` に MainStageCheckpoint がなく、シーン全体にも sectionNumber: 2 が存在しない。ランタイムセットアップ後のチェックポイントも第3区間から始まる。

このため、第1区間を渡って第2区間へ進んでも復帰地点が更新されず、第2区間で落ちた際に第1区間へ戻される。

シーン再構築用 MainStageSceneBuilder.BuildSection1 には第2区間チェックポイントの追加処理があるが、現在の保存シーンへの実行時補完はない。

### 2. 本編への遷移後に危険物判定が欠ける — 隔離環境で再現、実機で要確認

Play Mode の Tutorial → MainStage → MainStage 再ロードで、次のコンポーネント数を記録した。

| 場面 | RopeSpikeHazard | PlatformOccludedLightHazard | 本編チェックポイント |
| --- | ---: | ---: | ---: |
| Tutorial 起動 | 3 | 0 | 0 |
| MainStage へ遷移 | 0 | 0 | 7 |
| MainStage 再ロード | 0 | 0 | 7 |

例外・Assert は 0 件で、クラッシュは再現しなかった。ただし判定がない場合、トゲや光を使った課題を成立させられない。

コード上、MainStageFloorCollisionSetup は起動時の RuntimeInitializeOnLoadMethod から呼ばれ、通常のシーン切り替えに対応する sceneLoaded 登録はない。Tutorial 起動時には MainStage 用処理を通らない。

注意：隔離シーンは DLL 参照へ変換しており、StageHazards.cs のようなファイル名とクラス名が異なる保存参照は変換できていない。このため上記の欠落数をそのまま元のエディター／配布ビルドの実測とは扱わない。遷移時の初期化経路の不足と、保存スクリプト参照を実機で確認する必要がある。本編直接起動との追加比較は Unity Licensing Client の接続失敗により未完了。

### 3. 残量の説明が実際と一致していない — 確認済み

本編初期残量 50。今回成功した橋長の組み合わせで、実際の TryReachSection とチェックポイント最低残量を用いて計算した。

| 経路 | 永久消費合計 | 自動補充 | 終了残量 |
| --- | ---: | ---: | ---: |
| 第6区間上ルート | 51（5+6+14+4+12+10） | 第9区間で +2、1 回 | 1 |
| 第6区間下ルート | 37（5+6+4+12+10） | なし | 13 |

この組み合わせでは残量不足による進行不能はない。ただし README の「必須消費44～45」「余裕5～6」「通常は最終区間で15→5」という説明と一致していない。別の橋長や再挑戦を含む全組み合わせの保証ではない。
