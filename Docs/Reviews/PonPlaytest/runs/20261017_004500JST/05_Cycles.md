# 周回記録｜仮説・反例・結論の更新

今回、通常キーによる実操作Aは0。以下の「条件変更」は固定コードの分岐と既存資料を比較したもので、キーを送ったり変数を書き換えた実験ではない。各周に既存知識があるAIとして参加し、初見のHumanの感情とは扱わない。

## 周1｜最初の説明が多過ぎるのか

- **対象/仮説**：T1の概要+手順が長く、最初の成功前に必ず読ませるためテンポが悪いのではないか。
- **条件の比較**：看板を開く人と、開かず通常移動する人の経路をソースで確認。
- **反例**：Zで任意に開く仕様。自動全画面説明ではない。開かない人に全文章の読書時間は発生しない。
- **更新**：「強制的に長文を読ませる」は撤回。Bで確認できる重複を減らし、Cで看板発見/理解/所要時間を調べる。看板やヘルプ自体の削除は推奨しない。

## 周2｜Qは照準方向へ自由に橋を作るのか

- **良い体験候補/仮説**：接続→身体を道に変えるのは強い。ただしUIの「この照準方向へ」が仕組みと合っていない可能性。
- **条件の比較**：接続中の照準・主人公位置による端点と、フックが持つ対の端点をコードで区別。
- **反例探索**：橋の長さが推奨値に固定なのかも確認。実際は端点間を満たす長さなら作れるため、自由度が全くないわけではない。
- **更新**：Bで生成端点は対応フック間、長さは消費・たわみへ反映。UIを「2つのフックの間」とし、自由度を残す説明が妥当。Humanの予測改善はC。

## 周3｜T4のQ不可案内は常に誤りか

- **対象/仮説**：T4では不可なら「右の緑フック」を勧め、原因を誤誘導するのではないか。
- **条件の比較**：残量不足、対象外、対端点距離不足、T4以外の枝を照合。
- **反例**：残量不足の枝はT4の枝より前。対象外フックなら右への案内が適切な局面もある。さらに短いヒモで正しい接続が成立するかは射程とtargeting graceに依存し、ソース分岐だけで実入力の再現を断定できない。
- **更新**：「全て誤案内」「再現済みのバグ」は却下。Bの条件分け不足リスクとして保持し、Cで到達できる不可状態を確認してから修正理由を確定する。

## 周4｜最後の橋は削るべきか

- **対象/仮説**：S10は橋10を作って歩くだけで、新しい判断がない。
- **条件の比較**：端点距離9、推奨10、入口下限11、Qの汎用条件、S9→S10チェックポイントを照合。
- **反例**：「長さ10しか受け付けない」は誤り。橋生成の条件は推奨値完全一致ではない。長さ9以上でも端点を満たし得て、余剰長はたわみと消費に反映する。また最後に身体を残す物語上の意味・ゴール前の余韻がある。
- **更新**：最も弱い課題候補というCは維持するが、無条件REMOVEはしない。S9後の締めへMERGEした場合と、最後の身体消費を残す場合を比較。資源の逆算が必須だという説明は、最低残量補充の存在に照らして弱める。
