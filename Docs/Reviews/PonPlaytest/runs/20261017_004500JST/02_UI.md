# UIと文章｜原文から完成形の提案へ

分類B＝既存画像と固定ソースの照合、C＝実Window/通常入力で確認が必要。今回Aはない。原文は固定Buildソースを優先する。過去画像の小数表記・テスト状態・古い残量例を現在の不具合に数えない。

## U01｜Q前の案内：橋を作る単位を正しく伝える（最優先・B）

- **画面/10/6固定Build原文**：Tutorial接続中。「この照準方向へヒモ足場を作る」「永久に使う長さ {n}」「Q：この方向へヒモ足場を作る」。`PrototypeHud.cs:233–244`。
- **必要情報**：Qでどこに橋ができるか、消費量、今作れるか。
- **問題**：固定コードは接続したフックと対のフックの間に生成する。接続後に照準方向や主人公位置を自由に選んで橋の端点を決める仕組みとは違う。「この方向」が誤った予測を招く恐れ。タイトルと操作文も同内容を反復。
- **扱い**：短くして意味を合わせる。消費は残す。
- **修正文**：タイトル「2つのフックの間に橋を作る」／資源「使うヒモ {n}」／実行可能時「Q　橋を作る」。詳細ヘルプに「作った橋からヒモを取り戻すことはできません。Rで直前の復帰地点からやり直すと、復帰地点に保存された状態に戻ります」。通常回収と区間の巻き戻しを分ける。
- **表示タイミング**：橋用フックに接続した時。作れない状態では実行可能の見出しを出さず、下記不可理由を表示。語の変更だけで生成仕様は変えない。

## U02｜Q不可の理由：長さ不足と接続先を分ける（B/C）

- **画面/10/6固定Build原文**：「足場にできません\nヒモを{最低残量}以上残してください」「この接続先では足場を作れません\nEで外し、右の緑フックを狙ってください」「ヒモが対岸フックまで届いていません\nEで外し、Wで長くしてください」。`PrototypeHud.cs:238–266`。
- **必要情報**：何が不足し、次に何を変えるべきか。
- **問題**：T4では残量不足以外のCanBuild失敗が一律に「右の緑フック」へ誘導される枝が、長さ不足の判定より先にある。正しい中央フックでも別理由で不可になった場合の案内が不正確になる可能性。該当入力で本当に到達できる状態かは未実測なので不具合確定にはしない。
- **扱い**：条件別に残す。汎用文を削るだけで解決した扱いにしない。
- **修正文**：残量不足「橋を作ったあとに、ヒモを{最低残量}残す必要があります」／長さ不足「橋にする長さが足りません。Eで外し、Wで長くする」／対象外「このフックからは橋を作れません」。方向指定は本当にその段階だけに限定。
- **表示タイミング**：Qができない理由を特定できる時。複数理由ならプレイヤーが次に直せる原因を1つ表示。最初に不可条件ごとの通常入力確認が必要。

## U03｜ヘルプ：省略で意味が変わっている条件（B）

- **画面/10/6固定Build原文**：「Space　ジャンプ」「W / S　次に使う長さを変更」「E　ヒモを接続・解除」「Q　接続中のヒモを足場化」「F　中央Hookを外してまとめる」。[旧静的ヘルプ画像](evidence/images/E03_help_fixture.png)。`StageOverlayControls.cs:266–276`。
- **必要情報**：押すキーに加え、その操作を使える状態。
- **問題**：Spaceはヒモ接続中には使えず、W/Sは未接続時だけ。新規Eは通常接地中、S6連続フックだけ空中再接続例外。Qは任意の接続では作れない。Fは未接続で2本が集まる中央を狙う必要があり、S3では戻り足場スイッチにも使う。
- **扱い**：ヘルプに必要条件を保持。全条件をHUD常時表示にはしない。英語Hookをフックへ統一。
- **修正文**：

| キー | 主行 | 必要な補足 |
|---|---|---|
| A / D | 移動・振り子の加速 | 現状維持 |
| Space | 足場からジャンプ（ヒモ未接続時） | 接続中はEで外す |
| W / S | 次に使う長さを選ぶ（未接続時） | 接続中はEで外す。選択値は次の接続で使う |
| 矢印 | ヒモを掛ける向きを変える | ↑/↓は真上/真下 |
| E | フックに掛ける・外す | 掛けるときは通常足場の上。S6下ルートでは外した直後に次のフックへ掛けられる（距離と時間の条件あり） |
| Q | 接続したフックから橋を作る | 橋用の組があるフックのみ。橋にした分は残量を消費 |
| F | 中央フックを外し、橋を1本にする | ヒモを外し、2本が集まる中央を狙う。S3のスイッチでは戻り足場を出す |
| R | この区間からやり直す | 橋・ヒモ残量も直前の復帰地点に保存した状態へ戻る |
| Z | 近くの看板を読む・閉じる | Tutorialのみ |

- **表示タイミング**：Tabで任意に開く詳細。S6の例外とS3スイッチは各現場にも短く表示。詳細を1枚へ詰めるなら実Windowの文字量再確認が必要で、長文化のまま採用しない。

## U04｜木製ボタンとキー専用ラベルの見分け（B/C）

- **画面/10/6固定Build原文**：失敗「R　この区間から再挑戦」、看板「Z　区間{n}の看板を読む」「Z　看板を閉じる」。木製ボタンの見た目。
- **必要情報**：クリックできるか、どのキーで進むか。
- **問題**：`DrawWoodButtonLabel`は描画のみ。失敗と看板の制御はR/ZのGetKeyDown。対してポーズ/クリアは同じ外観の`WoodButton`でGUI.Buttonを使う。見た目が同じなのにクリックの有効性が違う。実クリックを試したという主張ではない。
- **扱い**：操作体系を保ち、ボタンらしく描く箇所のクリック対応を比較候補にする。代案はキー専用表示の外観を区別。現段階では実装しない。
- **修正文**：「R　この区間からやり直す」「Z　看板を読む」「Z　閉じる」。クリック可能にするなら文字へ「クリック」まで足す必要はない。
- **表示タイミング**：失敗が確定して再試行可能になった時、看板の範囲内、看板表示中。hover/focus/クリック/キーが同じ結果になるかCで比較。

## U05｜T1看板：最初の動作へつながる短さ（B/C）

- **画面/10/6固定Build原文**：概要「青いHookへヒモを掛け、歩き出して振り子になり、対岸へ渡ります。」、手順「1　W / Sで長さ、矢印キーで向きを調整\n2　青いHookへ照準を合わせて E\n3　右へ歩いて振り子になり、対岸へ着地」。
- **必要情報**：青フックに掛け、足場から踏み出すと振り子になる。
- **問題**：概要と3手順の説明が重複。ただし任意看板なので強制読書とは数えない。操作条件の補足は別に必要。
- **扱い/修正文**：概要「青いフックに掛けて、対岸へ渡ろう。」／手順「矢印で狙い、Eで掛ける。Dで踏み出し、振り子で渡る。」／長さに困る人用に「W/S：次に使う長さを選ぶ（未接続時）」を残す。
- **表示タイミング**：看板を開いた時。長さ・照準の情報を全部消さず、動く図と対応する順で提示。

## U06｜T2看板：答えと因果の順番（B/C）

- **10/6固定Build原文**：「長さ8では底が下がり、トゲに当たる」「Eで外し、W / Sで長さ6～7を選ぶ」「もう一度 Eで掛け、トゲの上を渡る」。
- **必要情報**：長さで最下点が変わる、変更には解除が必要、具体値が必要な人の救済。
- **問題**：試す前に正解値を知ると、地形を見て判断する学習かキー順記憶かを区別できない。
- **扱い/修正文**：最初「ヒモが長いほど、低く振れます。トゲに当たらない長さを選ぼう。」／詳しいヒント「Eで外し、W/Sで6〜7にして試す」。
- **表示タイミング**：因果は看板の最初、値は任意の詳しいヒント。新しいヘルプ階層を作る負荷が大きければ、まず同じ看板内の優先順位だけを比較。

## U07｜T3看板：消費を保持（B）

- **10/6固定Build原文**：「編む――初めて、体が減る」「頭上にHookがない谷です。対岸の緑フックへ掛けたヒモを足場にします。」「残量を7使ってできた橋を歩いて渡る」。残量例は固定ソースで99→92へ修正済み。
- **必要情報**：振り子では渡れない谷、橋で7消費し、使った身体が道になる。
- **問題**：Hook/フック、足場/橋、体/残量が同時に入る。説明の正しさを残して用語を揃えられる。
- **扱い/修正文**：タイトル「ヒモを橋にする」／概要「対岸へヒモを掛け、Qで橋にしよう。」／消費「体のヒモを7使い、橋として残します。99 → 92」。文章と図の両方で身体と道の関係を残す。
- **表示タイミング**：T3看板とQ実行前。旧99→93の不具合を再発扱いしない。

## U08｜T4看板：2本のままでは通れない理由を残す（B/C）

- **10/6固定Build原文**：「2本の足場を中央で外し、梁の下を通れる1本の橋へまとめます。」「左岸→中央→右岸へ長さ6の足場を2本作る」「中央の青いHookへ照準を合わせる」「Fで中央を外し、深くたわんだ1本の橋を渡る」。[旧静的看板](evidence/images/E06_sign4_fixture.png)。
- **必要情報**：2本のままでは梁に当たる、中央を外すと下がる、F条件。
- **問題/追補で限定**：長さと順序に加え、アニメ字幕には「2本の橋では通り道が高い」「梁があって進めない」「F　中央を外すと1本に下がる」が既にある。理由の説明が無いとは言えない。字幕の因果説明は図の内部経過時間9秒以後に出るため、短時間で閉じた場合に見逃す可能性をCとして比較する。Fを押せたことと形状理解は別。
- **扱い/修正文**：概要「2本の橋では、梁に当たります。中央のフックを外すと、橋が下がります。」／操作「ヒモを外し、中央の青いフックを狙ってF。」／補助「左右に長さ6の橋を1本ずつ作る」。
- **表示タイミング**：理由を看板の先頭、操作は2本ができた時に再確認可能にする。理由を消してFだけにしない。

## U09｜HUDと右下案内の重複（B/C）

- **10/6固定Build原文**：HUD「Tab　操作説明」＋右下「Tab：操作確認　Esc：ポーズ」。
- **必要情報**：操作説明とポーズへの入口。
- **問題**：同じTab案内が二箇所、呼称も説明/確認で揺れる。固定ソースで双方の描画経路あり。通常画面での重なり具合は未確認。
- **扱い/修正文**：案内を一箇所に統合し「Tab　操作説明　Esc　ポーズ」。残量、現在区間、次に使う長さは保持。
- **表示タイミング**：通常プレイ中。看板/ヘルプ/失敗/クリアの操作表示へ重ねないよう実Windowで確認。

## U10｜タイトル/選択画面の制作注記（B）

- **10/6固定Build原文**：「制作：bq24014-cmd　／　Unity 6.3 LTS　／　使用素材はREADME参照」。
- **必要情報**：遊ぶ場所と開始方法。制作・素材情報は参照先として必要。

- **扱い/修正文**：主画面からクレジット/配布READMEへ移す候補。主画面に残すなら「制作：bq24014-cmd」。

## U11｜未実装ステージと約束の文言（B/C）

- **10/6固定Build原文**：「COMING SOON / 追加予定」「新しいステージを追加予定です。\n今はまだあそべません。お楽しみに。」「追加をお楽しみに」。
- **必要情報**：ここは選んでも遊べない。
- **問題**：同じ未提供情報を3か所で説明し、遊べない島が選択対象になる。画面の手作りの地図という魅力はあるため、島そのものの削除は別判断。
- **扱い/修正文**：短縮「準備中」。説明「この場所はまだ遊べません。」は選んだ時だけ。確定していない提供時期は書かない。
- **表示タイミング**：未提供の島にフォーカスした時。開始ボタンは無効と分かる外観。フォーカス移動の実感は未確認。

## U12｜ポーズの時間依存の説明（B）

- **10/6固定Build原文**：「100％＝これまでの音量 ／ 0％＝無音\n設定は自動保存されます。操作方法はTabで確認」。
- **必要情報**：音量と保存方法。
- **問題**：「これまで」はどの版・基準を指すか不明。操作説明入口は別にもある。
- **扱い/修正文**：「0％で無音。音量は自動で保存されます。」。「初期音量に戻す」は機能が分かるためKEEP。
- **表示タイミング**：音量設定の近く。スクロール領域があること自体は欠点にしない。[旧静的ポーズ](evidence/images/E04_pause_fixture.png)。

## U13｜ステージ選択へ戻る警告（B）

- **10/6固定Build原文**：「現在の区間・ヒモ橋の進行はリセットされます。\n音量設定は保持されます。」
- **必要情報**：戻ると失う進行と、戻る/中止。
- **問題**：「現在の区間」が区間だけ失うようにも読める。再開が第1区間ならその結果を先に示す方が具体的。
- **扱い/修正文（条件付き）**：「このステージは最初からやり直しになります。音量設定は残ります。」。10/6固定版では通常Scene再入場でロードし、MainのAwakeが第1区間・最大残量へ初期化、プレビュー開始フラグはSceneで0、永続進捗はクリア印のみというソース/Scene条件を確認した（追補06参照）。ただし実Buildの再入場は未操作なので、文案の最終確認はC。
- **表示タイミング**：ポーズから選択へ戻る直前の確認。この損失の案内は削除しない。実際の進行保存範囲は通常操作でも再確認する。

## U14｜失敗画面の気遣い文と原因（B/C）

- **10/6固定Build原文**：「もう一度、編み直そう」「足を踏み外しました」「少しだけ休んで、同じ区間からもう一度。」。本編は「同じ区間から、落ち着いてもう一度。」
- **必要情報**：失敗し、どこから再試行でき、何が戻るか。
- **問題**：「休んで」「落ち着いて」は次の判断に寄与しにくく、原因を説明しない。「足を踏み外した」だけではトゲによる解除後落下と解除タイミング失敗を区別できない。今回の失敗を観測したわけではない。
- **扱い/修正文**：見出し「落下しました」。補足「Rで、この区間の始めから。橋とヒモ残量も戻ります。」。原因が実際に記録できている場合だけ「トゲに触れて、ヒモが外れました」等を候補にする。ログにない原因は捏造しない。
- **表示タイミング**：落下演出が終わり再試行できる時。短縮が復帰待ち時間の改善そのものだとはしない。

## U15｜クリア画面の断定と見取り図（B）

- **10/6固定Build原文**：Tutorial「ヒモを掛ける・長さを選ぶ・足場にする・まとめるを習得しました」。地図「ピンク：クリア時に残ったヒモ橋　／　床と高さを簡略化した見取り図」。
- **必要情報**：クリアした、残した道、本編へ進む方法。
- **問題**：到達は理解の証明ではなく「習得しました」は過大。地図の技術説明は凡例より長い。
- **扱い/修正文**：Tutorial「本編へ進もう。」／凡例「ピンクは、あなたが残した橋」。見取り図・残量・橋本数はKEEP。
- **表示タイミング**：クリア後。既存Clear画像の橋0/残量50は検証状態であり、作品UIの誤表示としない。

## U16｜異常系の技術語（B/C・低頻度）

- **10/6固定Build原文**：「ステージが見つかりません。Build Settingsを確認してください。」。
- **必要情報**：開始できないことと、戻る方法。
- **問題**：配布版のプレイヤーはBuild Settingsを修正できない。Debug.Logだけの技術文は製品UI問題へ混ぜないが、この文はStageSelectionErrorとして画面に渡す経路がある。
- **扱い/修正文**：プレイヤー向け「ステージを開けませんでした。別の場所を選んでください。」。詳しい原因は開発ログに残す。
- **表示タイミング**：読み込み失敗時だけ。今回その異常を起こしていない。

## 表示の整理で注意すること

- `MainStageHud.DrawSectionFourGuide/FiveGuide/...`、`PrototypeHud.DrawSectionFourGuide`の文章は固定ソースに残るが、通常OnGUIからの呼び出しがない。これらを「今の画面に長い攻略文が常時出ている」根拠には使わない。
- 通常フックの青/橋用の緑という説明には、T4/S9中央の青い兼用フックという例外がある。「緑ならQ、青ならQ不可」と単純化しない。
- Proof比較ラベル、Development Build表示、診断中の光線・カーソル・テスト用数値を本編UIの欠点として数えない。
- 「AIが書いたから悪い」と著者を推測しない。冗長さ、不要な気遣い、条件欠落、操作結果との不一致を具体的に扱う。
