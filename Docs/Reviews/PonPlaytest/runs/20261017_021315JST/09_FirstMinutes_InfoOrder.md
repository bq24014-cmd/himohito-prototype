# 最初の3分で問う情報の提示順｜訂正差分

**時間は未計測、A=0。** 10/6 FriendPlay固定Buildのコードと既存画像によるBの整理。T2～T4やMainの最初の橋を「3分以内に到達する区間」とは扱わず、後続の情報提示順として参照する。今のProductionや演出候補2の画面は評価していない。

## 今回磨いた結論

1. Tutorialは、操作説明や全画面看板を自動で順番に読ませてから操作を解放する構造ではない。紹介は自動だが、TabヘルプとZ看板は任意。実際に何文字/何秒読むか、最初の成功までの時間は不明。
2. **T3看板には、初めから「掛けるだけなら消費なし」と身体を使う意味があり、消費7と99→92の例もある。** 説明の新設より、既存の意味とQ生成位置の表現を合わせる方が小さい。
3. **T4の概要には、最初から「梁の下を通れる」目的がある。** アニメ後半の字幕だけを根拠に「理由を知るまで待たせる」と断定しない。後半には高い→梁→外すと下がる、という明確な因果が追加される。
4. 任意看板を読まない/Tabだけ/Main直入りでは、同じ情報を得るとは限らない。Mainは消費後のゲージと−n表示がある一方、通常OnGUIにTutorialのQ前Popupを出す経路はない。選択長そのものはQ前にもHUDで見える。**数値が無いという問題ではなく、選択長と消費の対応を事前に読めるかの問題。**

## 読まない経路・Tabだけ・Main直入りを分ける

| 経路 | すでにある手掛かり | 残る仮説/小さい比較 |
|---|---|---|
| TutorialでTab/Zとも開かない | 小看板のE/W/S/Q/Fと図、地形、HUD、T3接続後のQ予告 | 書面の接続条件や統合因果を読まない。ただし絵と試行で分かる可能性がある。「読まないと進めない」と断定しない |
| Tabだけ開く | 8キーの用途、概要、再確認できる入口 | W/Sを接続中に押す/空中Eが反応しない時の理由、Qが資源を使う意味を説明できるか。全条件の長文を8行へ足す前に、短い主行と現場の条件を比較 |
| 全文看板を読む | T1の目的/行動、T2の長さ因果、T3の無料接続/消費、T4の梁下への目的 | 既に説明がある項目は新設しない。必要な瞬間に読み返せるか、正解値の先出しが考える機会を減らすかは実試遊で確認 |
| Mainを先に選ぶ | 箱の目的、残量50と次の長さ、Tab、消費後の表示 | Tutorial由来の知識を前提にしない比較が必要。Q前に「どこへ/何を使う」を予測できるかをMain最初の橋でも確認する |

## 既存画像で分かる文字量と、分からないこと

- E01旧メニュー：選択中のMain説明は2行、主要ボタンは1行で画像に収まる。目的をもっと長く説明する必要を、この画像からは認めない。選択中の説明が切り替わるため、全Entryの文章を同時に読む画面でもない。
- E03ヘルプfixture：1280×720で8つの主行は各1行、概要と閉じる表示もある。現行案に全ての条件・例外を同じ列へ入れると、元の一覧性を失い得る。固定コードは2列/可変の文字折返しであり、改稿後の収まりは未検証。
- E06 T4 fixture：手順1の末尾「る」が次行へ回り、手順3も折り返す。短い文節へ整える理由にはなるが、文字が欠けた/読めないという再現ではない。旧概要は「深い谷の下」、10/6ソースは「梁の下」なので、旧文を固定版の原文として批判しない。
- E02旧HUD：残量・選択長・Tabがまとまっており、小看板にE/W/Sの図が見える。旧選択値・小数表示・Z案内の有無を固定版の開始状態や新たな不具合の根拠にしない。

画像は既存PNGの閲覧だけ。新しい実画面や改稿見本は作っていない。既にHumanが閉じた看板の可読性や99→92等を再オープンする指摘ではない。

## 朝の優先順位への影響

**上位5案の順位を入れ替える実プレイ証拠は得ていない。** ただし第1案Q予測の比較対象は、TutorialのT3/T4だけでなくMain直入りの最初の橋を含める方がよい。第2案の操作条件・Tabだけの経路は、第4案T4の文章磨きより先に見る、という既存順序を補強する。

最初に取り組む既存の1件は、Q案内で生成位置と消費を予測できるかの小さい比較の採否判断。ポーズ中入力の最小確認は、前のUI状態追補に記した別の未実施確認として保持する。確認で機能上の問題が実証された場合に、親/Humanが優先順位を見直す。

今回残した未確認は、最初の成功までの実時間/実読書量、小図だけでの意味理解、任意資料の発見、Main直入りの資源判断、改稿後の折返し。未到達の試遊結果や人間の感情として埋めない。
