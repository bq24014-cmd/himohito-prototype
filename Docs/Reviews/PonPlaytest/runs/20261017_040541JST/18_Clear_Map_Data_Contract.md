# Clear地図｜データ契約と凡例案の差分

**A=0、親レビュー済み・保存準備中（remote照合前）。** 10/6固定Build付属Sourceの10ファイルをBuildInputsと照合した読み取り。新規入力、実クリア、画像/音取得、再Build、Production変更なし。S5公開分から独立した追補。

## 既存根拠を増やし直さない

9/9のLEARNING_LOG:4837–4843は、残る有効な橋の複製、歩行軌跡/累計生成数を描かないこと、F後の1本、固定残量、独立した縦横縮尺を既に明記。今回はその再発見を数えず、**R・経路選択と文案の整合**に限る。既存U15の「習得しました」は別途指摘済みで重複計上しない。

## 表示へ入るもの／入らないもの B

|表示|実際のデータ|読めないこと|
|---|---|---|
|ピンクの橋／本数|結果View初回生成時、ownerのbuilderに残るactiveなenabled EdgeColliderの曲線。配列長が本数。|歩行軌跡、踏んだ順、Q累計、F前2本の履歴。|
|床・rail・START・GOAL|同Sceneのactiveな床候補の上面/左右端と開始床・箱。訪問条件なし。|踏んだ床だけの経路、hook連続移動、落下/振り子の軌道。|
|残量／最大|同時点のCurrentLength／MaximumLengthをsnapshotへ固定。|全試行の総消費、失敗で使った量、補充量。|
|本編の補充回数|高い番号のCP受理で、残量が下限未満だった際の加算。|Rの回数、失敗数、補充された長さ。|
|本編の時間|Main HUDの開始値からTime.timeの差を結果画面で固定。Rでは開始値を更新しない。|最後の成功試行だけの時間、実操作秒数の計測。|

snapshotは結果画面の初回生成時で、到着瞬間を逐次記録する機能ではない。縦横別縮尺・各snapshotの範囲で投影するので、図から実距離/必要長を測らない。橋のない谷をSTARTからGOALへ線で埋めることもしない。詳細は[契約と条件ケース](evidence/clear-data-contract.json)。

## 今回の差分 B：R・統合・経路

- **R**：保存した橋の端点/長さを再生成し、残量も保存値へ戻す（仕組み自体は既存07）。その後Clearへ進めた場合、未保存の試行橋は地図に残らない。失敗の痕跡を出さないことは契約どおりであり、歩行/消費履歴の欠損バグとしない。
- **F**：統合前2本を除き、合計長の1本を作る。現在本数は減るがF自体は消費/返還しない（既存07）。**橋が少ない＝節約した、とは判定できない。** 統合後が保存されていればR後もその1本が対象。
- **経路選択**：S6下の通常接続/解除移動を描くデータはない。使わなかった上側の床もactiveで条件に合えば描く。上橋が残れば選択の一端は示せるが、橋の空白だけで下ルート利用を一意に証明できない。**橋の有無は、完全な経路ログではない。** 実際に通ったことの主張ではない。
- **余分な橋**：踏まなくても、有効なまま残れば収録条件に入る。固定配置にそのような合法クリア例があると実証したわけではない。現在状態だけから、通行に必要だった橋を選別していない。

## 原文／案文の照合：現行UIに混同の確証はない

|原文・場所|必要情報／問題|扱い・短い案|
|---|---|---|
|現行「あなたが残した道」＋「ピンク：クリア時に残ったヒモ橋 ／ 床と高さを簡略化した見取り図」|凡例は現在残る橋と簡略図だと既に限定。歩いた軌跡や総消費と明記していない。|**KEEP。** 比喩的な見出しを即誤表記としない。|
|既存U15案「ピンクは、あなたが残した橋」|短縮で「クリア時」「見取り図」の条件まで消していた。実際の誤認は未観測。|**レビュー文書の凡例案へ適用**：「ピンク：クリア時に残った橋 ／ 見取り図」。必要情報を「クリア時に残る橋と残量、次に進む操作」へ明確化する案は未適用。ゲームUI本体の文言は変えていない。|
|現行「残したヒモ橋 n本」「補充 n回」|sourceの現在本数/補充発生回数に対応。累計生成/失敗と書いていない。|**KEEP。** 集計定義はレビュー資料に置き、製品画面へ技術説明を増やさない。|

S10の橋と地図の関係は既存14で条件付きに訂正済み。費用だけを省く仮定から地図形状が変わるとは言わず、そこを新たな修正件数に数えない。[案文台帳](evidence/clear-copy-ledger.json)。

## 次の試行へ教えられること：設計所見 C

残量と残した形を並べれば「この形を残した時、自分にはどれだけヒモが残ったか」を振り返る材料になる。ただし、実寸での最適長、どの失敗が多かったか、余分な橋だったか、別ルートの方がよいかを自動説明する画面ではない。**これを見れば節約方法を学べる/再挑戦したくなる、という効果は未実証。** 完成物の余韻として残す価値と、攻略成績表へ機能を増やす案を分ける。今は新しい経路/支出ロガーを要求しない。

接続復旧後の最小確認は、普通に到達できたクリア画面で「この図のピンクは何を示していると思う？」と聞き、本人が選んだ動作と図をどう結び付けるかを見ること。誘導前の説明と、その後にR/F/ルート差を指定した比較は別記録にする。クリアできなければこの確認は未実施で止める。紙面の凡例比較は可読性の比較であり、実ゲームで学習が成立した証拠へ替えない。

推薦は**地図/残量/現在本数KEEP**。U15の凡例案へ限定語を戻した。上位5件/朝1件の順位を変える根拠は増えていない。ゲーム本体と優先順位本文は未変更。
