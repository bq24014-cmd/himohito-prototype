# C05：平らなヒモ端の実メッシュ接触／VFX非依存の切断

基準：03e546d1689859eca493f7d24acf815e2c7e9725。対象は Main Section 2 Front Spike 1個。隔離候補1案、Production未統合、Human Review待ち。C11/C18はHOLD。

## 結果

実PlayerのLineRendererをCamera付きBakeMeshで取得すると、端・角の分割数はともに0、alignmentはView、ヒモ幅は約0.16worldだった。実際の頂点と三角形でも端は平ら。下降0.45の旧切断フレーム109では刃とメッシュ間に **0.01892523world（720pで0.783px）** の隙間があり、丸い端を仮定した従来判定は早すぎた。

接触判定を実描画三角形と刃ポリゴンの重なりへ変更。現在配置の下降0.45では、実Playerの観測フレームもフレーム間のメッシュ判定も長さ7を切断しなかった。体のみの接触は切断されない。

対象だけをさらに **上へ0.03world（下降0.45→0.42）** 調整すると、同じ入力の長さ7でメッシュが刃へ実際に重なり、切断した。これは実Playerで確認した小さな修正量であり、任意入力における数学的な最小値とは主張しない。基準からの変化は720pで約1.24px。持ち手は新しい支持基準に追従し、倍率・輪郭・材質・上向き・共通支点を保持。Cameraは下降0.95、ズーム8.7のまま。

長さ7も今回は基準と同じゲーム時刻2.18秒・frame109で切断されたため、記録した300フレームの物理・残量・追従Camera差は0だった。配置は変えたが、切断時刻がたまたま同じ条件で成立した結果であり、他入力での切断時刻一致を保証しない。

実メッシュに対する長さ5の最小余裕は1.987029world、長さ6は0.989264world。これは旧中心線カプセルへの距離でなく、実際の三角形と刃との距離。実測は[Summary](QA/Summary.json)と各RopeContact.jsonに保存した。

## VFXから独立した切断

成立した接触について、切断前のVFX保存を試し、成否を記録する。その後は保存の成否にかかわらず既存DetachAndRefundを1回呼び、成功通知と音v4を発生させる。保存が成功した場合だけVFXが生成される。

保存失敗時は保留中のコピーを破棄して、次の成功通知が古い保存を使わないようにした。通知先が例外を出しても、成立済み切断・返却を取り消さず、他の通知先へ進む。無効／強制保存失敗のケースでは実際にVFX 0を確認した。VFXを成功扱いにしていない。

返却回数は既存返却処理の呼出を計測したもの。本作品の通常接続は残量を減らさない仕様で、今回の切断前後は残量50→50。返却量が50増えた意味ではない。

## フレーム間の代表2ケース

[MeshCases.json](QA/MeshCases.json)は実Windows Player内の独立した診断LineRendererをBakeし、対象ハサミの刃形状を使ったテスト。通常ルート・Human操作ではない。両者が動く2観測時刻を作り、同じ補間時刻で三角形と刃を評価した。

1. 前後フレームでは離れているが途中に接触：前距離0.334999、後距離0.286149world。補間率0.233142で接触を検出し、切断・返却・音・VFX各1回。
2. 同じ領域を異なる時刻に通る：両者を同じ方向へ移動し、同時刻では隙間が残る配置。swept領域だけでは重なるが、切断・音・VFX 0。

接触時刻は7.024661秒、実際の切断通知・音開始・VFX生成は観測フレーム末の7.039998秒（差約15.34ms）。物理を過去へ戻していない。接触時の経路と点、現在時刻の経路と同じ材質位置を両方保存する。

診断ではその材質位置が約1.157world移動していた。表示コピーは現在の経路から開始し、実際の表示自由端を読み戻した切替時ジャンプは0。過去の接触位置へヒモ全体を戻さない。一方、この極端な移動では過去の接触点と現在のVFX中心は一致しない。この時間差は残る制限で、自然接触では現フレーム接触のため差0。任意速度で完全な時刻一致を達成したとは扱わない。

連続判定は観測した実三角形と両刃の頂点を同一時刻で線形補間する。実機の診断2ケースは通るが、大きな回転の厳密な連続曲線や全入力・全開閉位相を保証するものではない。
