# ステージ選択

旧タイトル画面を外し、起動直後からステージ選択を表示する。←→・A/Dまたはおもちゃの島／布製ラベルのクリックで選択し、Enter／「ここであそぶ」で開始する。Tab／「操作説明」で説明を開き、Esc／「ゲーム終了」で終了する。Unity Editorでは終了はPlayモード停止になる。

操作説明はTab・Escまたは「閉じる」のクリックで閉じる。説明中は背後の選択・開始・終了を無効にし、閉じたフレームも入力を消費する。説明を閉じるEscでゲームまで終了しない。開く音は維持し、閉じる音は追加しない。

現在はチュートリアルと本編の2ステージをどちらも選択でき、3つ目に「つぎの冒険／COMING SOON・追加予定」を表示する。追加予定の島は布をかぶせ、手前の道を途切れた毛糸にする。クリアで解放されるステージではなく、今後の追加を知らせる枠。選択すると案内を読めるが、開始ボタンは「追加をお楽しみに」となり無効。Enterでも遷移しない。公開日・具体的な内容・追加数は示さない。

区間選択ではなくシーン単位の選択。本編50・チュートリアル99の第1区間から開始し、通常のカメラ紹介を維持。ポーズ・失敗・クリア画面からの戻り先もステージ選択に統一する。戻った後も新規開始で、途中セーブ／解放条件は追加しない。クリア済みの印と音量設定を保持し、チュートリアルクリア後の本編への移動も従来どおり。

両ステージのクリア画面に「Esc ステージ選択へ戻る」を追加。キーとクリックのどちらでも操作でき、隣の「Enter 本編ステージへ」／「R 本編を最初から再挑戦」もクリックできる。確認画面は挟まず、結果表示中だけ受け付ける。クリア確定前・演出中の遷移と、同じ結果画面からの重複読み込みを防ぐ。読み込み先は `StageCatalog.TitleScenePath` を参照し、未登録なら現在の結果画面を維持してエラーを記録する。戻ったフレームは既存の `titleEnteredFrame` のガードで開始・終了を受け付けない。

## クリア済みの印（2026-09-10）

クリアした島に、ピンクの毛糸旗と「CLEAR」の布タグを表示する。ゲームのヒモ橋と同じ毛糸テクスチャ、マップの布素材、既存のM PLUS Rounded 1cで描画し、選択中の刺繍枠とは独立した印とする。旗は島に固定し、カメラ移動や点滅は加えない。印の上も従来の島のクリック領域として使える。

`StageProgress` が `HimoHito.StageProgress.v1.Cleared.<id>` のPlayerPrefsへ保存する。両コントローラのクリア演出待ちが終了し、結果画面へ切り替わる時点で `MarkSceneCleared(gameObject.scene.path)` を呼ぶ。利用可能なカタログ項目の完全一致するシーンパスだけを記録し、同じシーンを複数IDで登録した場合は該当する全IDが対象。再クリアでは書き直さず、途中の失敗・区間到達・メニュー復帰で新たに印は付けない。

保存済みでも未クリアでも選択制限は変えない。追加予定の島は印を表示せず、開始も従来どおり不可。過去の履歴は保存していなかったため、導入後にクリアした分から記録する。端末内の記録のみで、途中セーブ、クラウド同期、別端末への共有、実績サービス連携は含まない。

本編の再挑戦／落下監視もクリア演出中は停止する。従来の `IsClear` だけでは演出待ちの間にRで再挑戦でき、古いコルーチンが再挑戦後にクリアを確定するため、`IsCompleting` で結果確定前も守る。チュートリアルの既存の演出中入力ガードは維持する。

検証：隔離Unity 6000.3.21f1でコンパイル成功。保存・完了待ち・失敗／再挑戦・無効データ・IDによる記録維持の164項目、別Unityプロセスで保存を読み直す57項目が成功（`.codex_tmp/CraftUiCheck/StageProgressWrite-final.log`、`StageProgressRead.log`）。実コントローラの完了コルーチンを検証側で進めた状態テストであり、ゴールへの手動通しプレイではない。検証用PlayerPrefsは別company/productで、ユーザーの記録へテスト用クリアを付けていない。

確認画像：[未クリア](Images/StageSelection-Uncleared-v1.png)、[チュートリアルだけクリア](Images/StageSelection-TutorialCleared-v1.png)、[両方クリア](Images/StageSelection-Cleared-v1.png)。検証用の記録で製品の表示処理を描いたプレビュー。1280×720・640×360・800×600で実フォントの収まりとGUI状態復元、島／ラベル／印の端のクリック、追加予定の開始拒否を確認し、52項目成功・0失敗（`.codex_tmp/CraftUiCheck/StageProgressUi-verified.log`）。固定のEditorWindowでゲーム内座標のマウスイベントを注入し、撮影用のタブ余白だけを検証側で除外している。

## 選択した島を毛糸で囲む（2026-09-10）

従来の瞬時に切り替わる刺繍枠を、島の周りへ毛糸を一周させる一度きりの演出に置き換えた。0.32秒で左側から一周し、残り0.08秒で短いヒモ端を寄せて結び目を作る。合計約0.4秒後は静止する。ゲームと共通の毛糸テクスチャ、既存の結び目を使い、新しい画像・音・光・カメラ移動は追加しない。

`StageSelectionWeave` は選択中の固定ID・経過時間だけを保持する表示用の状態。`StageSelectionView` がIMGUIの描画から独立した `Time.unscaledTimeAsDouble` を渡し、同じ時刻のLayout／Repaint／入力イベントで二重に進めない。メニュー操作が無効な間は時計を停止し、再開時は隠れていた時間を足さない。操作説明を開く／閉じるだけでは編み直さない。

初めて表示した島と別のIDへ切り替えたときに開始する。同じ島の再クリックや左右端での入力では再発火せず、連続入力では最後に選んだ島だけを描く。3件ごとのページでもローカルの表示番号ではなくIDを使う。新しい選択枠は島の絵を囲む楕円とし、上の選択表示・下の名前ラベル・CLEARの旗とタグを維持する。装飾はクリック領域を持たず、開始可能かどうかは引き続きカタログの `available` だけで決まる。追加予定も選択演出は出るが、開始できない。

検証：隔離Unity 6000.3.21f1でコンパイル成功。時間制御は30／60／144fps、同時刻の繰り返し、連続選択、停止／再開、長時間放置、異常な時刻のテストに成功（`.codex_tmp/CraftUiCheck/SelectionWeaveState.log`）。実描画は29種類の状態で170項目成功・0失敗（`SelectionWeaveUi.log`）。0〜0.4秒の各段階、同じ島の再クリック、操作説明と時間倍率0、ページ0→次ページ先頭、1／2／3件の配置、1280×720・640×360・800×600、CLEARタグを含むクリック、保存済みクリア記録の不変更を確認した。検証側から時刻とマウスイベントを与えたテストであり、手動プレイの録画ではない。

完成状態の確認画像：[StageSelection-Weave-v1.png](Images/StageSelection-Weave-v1.png)。検証用の保存記録を表示したプレビューで、実ユーザーのクリア記録は変更していない。

## 毛糸で布を引いて開始する（2026-09-10）

Enter／「ここであそぶ」で開始した島から毛糸を約0.22秒で画面右へ伸ばし、その毛糸で紺色の布を約0.58秒かけて左から右へ引き込む。折り返した縁・小さな暖色の縫い目・ピンクの結び目を付け、島の拡大・上下動・画面の点滅は行わない。画面比率に関係なく布を上下左右の画面外まで描き、完全に覆った描画フレームを挟んでから開始処理へ移る。

チュートリアルは現在のメニュー兼用シーン内で開始状態を確定し、本編は `LoadSceneAsync` で読み込む。読み込み中も不透明な布を維持する。既存の `MainStagePreview` をゴール側へ準備してから、同じ布をさらに右へ約0.62秒で送り、ステージを左から見せる。布が残る間は紹介の待ち時間・移動・スキップ受付を止め、開き終わってから従来のカメラ紹介を進める。新しいカメラ経路・ズーム・効果音は追加しない。

開始を受け付けた後は、重複開始・選択変更・ページ移動・操作説明・Escによる終了を拒否する。追加予定の島や未登録のシーンでは開始せず、既存の案内を維持する。選択時の約0.4秒の毛糸枠が完成するまで待つ必要はない。開始時の区間・残量・物理・ステージ配置・クリア記録・音量設定は従来どおりで、布演出専用の保存項目は作らない。

実装は `StageStartTransition` が進行と読み込み、`StageStartCurtainView` が描画を担当する。新しい布テクスチャだけを追加し、毛糸と結び目は既存素材を再利用する。詳細仕様、フォールバック、素材の生成プロンプトは [STAGE_START_CURTAIN.md](STAGE_START_CURTAIN.md)。

## ステージを増やす

`Assets/Resources/StageCatalog.json` の `stages` 配列へ追加する。並び順が表示順。3件ごとにページが増える。

```json
{
  "id": "stage02",
  "title": "新しいステージ名",
  "subtitle": "STAGE 02",
  "description": "ステージの説明",
  "mapArt": "Art/Stage02MapIsland",
  "scenePath": "Assets/Scenes/Stage02.unity",
  "available": false
}
```

- `id` は重複しない固定IDにする。クリア記録の保存キーになるため、公開後は変えない。表示名・並び順・シーンパスはIDを保てば記録を引き継げる。異なるステージへ古いIDを使い回さない。
- `mapArt` は選択画面のイラスト。`practice`（練習場）・`toybox`（宝箱への道）を使用でき、省略時は後者。新しく描く場合は透過PNGをResources内へSprite（Single）として取り込み、Resourcesからの拡張子なしパスを指定する。見つからない場合も宝箱の島で表示を維持する。
- 未実装は `available: false`。追加予定表示となり、開始できない。シーン未作成でも登録可。現在の `id: upcoming` は予定を知らせる枠で、シーンパスを空にして配布対象から除外している。実ステージを追加する際は、この枠を実データへ置き換えるか、最後の予告として残す。
- 完成したら実際の `.unity` ファイルのパスを指定し `available: true`。
- 新しいシーン側に初期位置・残量・通常プレイ開始の処理を用意する。メニューはステージ固有のルールを変更しない。Tutorialはメニュー兼用のため特別に現在シーン内で開始する。EditorでMainStageを直接Playする開発用の動線は維持する。
- 布から既存のカメラ紹介へつなぐには、現在の `PlayerMover`・`Rigidbody2D` と互換性のあるプレイヤー、カメラ、および `MainStagePreview` が参照できるゴール側の対象を用意する。カタログへの追加だけでは紹介用の配置は作られない。紹介を準備できない場合は布を開いて元の操作状態へ戻すフォールバックとなるため、新規シーンごとに開始処理と紹介対象を確認する。
- 新しいクリア処理を作る場合は、結果の確定時に `StageProgress.MarkSceneCleared(gameObject.scene.path)` を一度呼ぶ。既存の `MainStageGoalZone` を使う場合は対応済み。カタログの登録だけで新しいクリア条件までは自動作成しない。
- EditorのBuild ProfilesのScene Listにも新シーンを登録し、有効にする。未登録の場合は選択画面にエラーを表示し、選択画面を維持する。
- `HimoHito > Build Windows Prototype` はカタログの利用可能なシーンを重複除外してビルド対象にする。メニュー用Tutorialは常に先頭。将来も手書きのシーン配列を更新する必要はない。
- JSON更新後はPlayを停止して入り直す。Domain Reloadを無効にしていてもカタログはPlay開始時に読み直す。

## 見た目

夜の工作台に置かれた紺色の布製マップと、小さな玩具の島を専用アートで新規制作。チュートリアルは青いフックとヒモ橋の練習場、本編は積み木を登って宝箱へ向かう島。布のラベルと刺繍の選択枠、ゲームと共通の毛糸テクスチャで世界観をそろえる。既存の操作説明の紙背景や浮いた主人公マーカーは使わない。M PLUS Rounded 1cは維持する。

ゲーム名をマップ上部へ置き、下部に「ゲーム終了」「操作説明」「ここであそぶ」の3つの布製ボタンと制作表記をまとめる。旧タイトルの描画処理を削除し、旧背景画像は既存素材として保持する。

1280×720の配置全体を画面内へ縮小／拡大し、入力領域も同じ倍率で変える。島の絵は縦横比を維持。2件は2つの島を広く配置、現在は遊べる2件＋予告1件の3つ、4件以降はページ切替で対応する。カタログにない選択肢は描画しない。選択画面は絵を跳ねさせたりカメラを揺らしたりせず、編み上がる毛糸枠とラベルの明るさで選択を示す。

素材・生成プロンプト・透過方法は [STAGE_SELECTION_ART.md](STAGE_SELECTION_ART.md)。背景に文字や道を焼き込まず、ステージの追加に追従できる。

追加予定の島は [STAGE_SELECTION_UPCOMING_ART.md](STAGE_SELECTION_UPCOMING_ART.md)。`mapArt: Art/HimoHitoStageMapUpcoming-v1` は予告用の専用素材で、既存アトラスと同じ処理で白背景を取り除く。採用中の画面は [StageSelection-Upcoming-v1.png](Images/StageSelection-Upcoming-v1.png)。

コード：`StageCatalog.cs`（データ）、`StageProgress.cs`（クリア済み記録）、`StageSelectionView.cs`（選択表示）、`PrototypeRunController.cs`（選択・開始の受付）、`StageStartTransition.cs`（布による開始・読み込み）、`StageStartCurtainView.cs`（布の描画）、`MainStagePreview.cs`（既存のカメラ紹介）、`WindowsPrototypeBuilder.cs`（配布対象）。JSON読込用にUnity組み込みの `com.unity.modules.jsonserialize` を有効化している。
