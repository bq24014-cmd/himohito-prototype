## 足場配置の実験：最初の振り子

### 仮説

紐を掛ける場所と着地点を分けると、接続方法だけでなく、振り子の勢いと解除タイミングも最初の区間で学べる。

### 今回変えたもの

- 開始地点の右上に、接続しやすい `First Hook` を置く
- その右側に、振り子で飛び移る `First Landing` を置く
- 物理値、操作、紐の最大長は変えない

### 3回プレイして記録する

1. 紐を掛ける操作は迷わなかったか：正直わかりにくかった。
2. 着地に勢いをつける必要があったか：勢いをつけすぎると、慣性でうまく着地できなかった。
3. 早く／遅く離した失敗の理由が分かったか：やっていることは簡単なので理解できた。
4. 面白かった瞬間：紐を引っ掛けた瞬間と、うまく着地できた瞬間。
5. 思っていたのと違った瞬間：最初より難易度が明らかに下がり、足場が3個ある意味もあまり感じなかった。

### 分かったこと

- 接続成功と着地成功には、それぞれ気持ちよさがある
- 勢いをつけすぎて着地点を越える失敗は、理由を理解しやすい
- 接続地点がほかの足場と同じ見た目だと、どこへ紐を掛けるか分かりにくい
- 足場を増やすだけでは選択にならず、それぞれに違う役割が必要

## 紐の残量実験：少ない数字だけで惜しさが生まれるか

### 仮説

接続中の残量が少なく見えると、紐を大切にしたい気持ちや「惜しい」という感情が生まれる。

### 今回変えたもの

- 紐の最大長と開始時の長さを `20` から `7` にする
- 操作、振り子の物理、接続地点、着地点は変えない
- 切断、残した紐の足場化、回復アイテムは追加しない

### プレイして記録する

1. 接続中の少ない残量が気になったか：現在の段階では評価しない。
2. 「あと少し紐があれば」と感じた瞬間があったか：現在の段階では評価しない。
3. 残量を見て操作や狙いを変えたか：現在の段階では評価しない。
4. 数字が少ないことで面白さが増えたか：現在の段階では評価しない。

### 今回の判断

- 紐を恒久的に消費する仕組みがない状態では、Q2の「惜しい」を考える段階ではない
- Q2は `No` と結論づけず、消費して進路を考える仕組みを試す段階まで保留する
- 最大長を小さくして数字だけを減らすことと、有限の身体を消費する面白さは分けて考える
- Q2比較用の仮値 `7` は基準値にせず、最大長と開始残量を `20` に戻す
- 今後の紐の総量は、メトリクス測定と消費方法の検証後に決める

## 操作不能の修正：地面の角への引っ掛かり

### 起きたこと

- 開始地面の右端で、プレイヤーの左下角と地面の右上角が接触すると動けなくなった
- 発生時は紐に接続しておらず、残量も最大だった

### 今回変えたもの

- プレイヤーの `BoxCollider2D.edgeRadius` を `0` から `0.08` にする
- 四角い見た目は変えず、当たり判定の角だけを少し丸める
- 移動、空中制御、振り子物理、紐の長さは変えない

### 確認すること

- 開始地面の右端で同じ姿勢になっても、左右移動やジャンプで抜けられるか
- 通常の着地や振り子の感触が変わっていないか

### 1回目の結果

- `edgeRadius` を `0.08` にしただけでは、別の足場の右上角でも動けなくなった
- 角に触れた状態では接地判定から外れ、空中移動の力より接触摩擦が強くなっていた

### 2回目の修正

- プレイヤー専用の物理マテリアルを実行時に作り、摩擦を `0` にする
- 角に触れたとき、空中移動の力で入力方向へ抜けられるようにする
- 移動速度、空中制御の力、振り子物理、紐の長さは変えない

### 2回目の結果

- 角には引っ掛かりにくくなったが、摩擦がないため足場の上で滑る感覚が生まれた

### 3回目の調整

- 摩擦だけを `0` から `0.1` にする
- 角から抜けられる低摩擦と、足場上で止まりやすい感触の両立を確認する
- ほかの物理値は変えない

### 3回目の結果

- 角への引っ掛かりと、足場上で滑る感覚の両方が改善した
- 摩擦 `0.1` を現在の基準値として採用する

## 提案1・案B：通常解除時の一部返却実験

### 仮説

紐を離すたびに使用量の一部が永久消費されると、現在の振り子の試行錯誤を残しながら、残量を見て掛け方を考えるようになる。

### 今回変えたもの

- 通常解除時の返却率を `70%` にする
- 接続時に使った長さの `30%` は、解除しても戻らない
- HUDの接続中表示に返却率を出す
- 落下して開始地点へ戻った場合は、従来どおり残量を最大まで回復する
- プレイヤー操作、振り子の物理、足場配置は変えない

### プレイして確認すること

1. 紐の残量を以前より意識したか
2. 無駄な掛け直しを避けようと考えたか
3. 30%の消費を理不尽またはストレスに感じたか

この段階では返却率を最終決定せず、提案2の「切り離して足場を残す」を追加する前の単独実験として扱う。

### 消費量を決める時期

- 返却率 `70%` はステージ検証を始めるための仮値とし、現時点では確定しない
- 「使用距離に比例して消費し、通常解除では一部だけ戻る」というルールを先に固定する
- 仮値のまま、紐を使うか温存するか迷う灰箱ステージを作る
- 基本ルートを遊べる段階で、クリア可能性、立て直しやすさ、残量不足の納得感を確認する
- その結果から、紐の総量と返却率を一緒に調整してからステージを仕上げる

ステージを確定した数値へ無理に合わせることと、資源を無視したステージを完成後に直すことの両方を避ける。

## 次の灰箱ステージは計画難易度型にする

### 採用しなかった案

「安全だが接続回数が多いルート」と「難しいが接続回数が少ないルート」の比較は、難しい操作に成功できる人ほど資源を温存できる構造になる。これは判断より操作技術を問う実行難易度型へ寄るため、採用しない。

### 採用する方向

- どのルートも、接続と着地そのものは難しくしない
- ステージ全体とゴールまでの候補を、動く前に見渡せるようにする
- 近い足場を順番に使うと、個々の使用量は少なくても掛け直しが増え、総消費量が大きくなる
- 遠い足場を先に使うと、最初の使用量は多いが、その後の距離が短くなり、総消費量を抑えられる
- 最後の接続に必要な長さを残せなければ、ゴールへ届かない構造にする

### 検証したいこと

1. 動く前にルートや足場の順番を考えたか
2. 失敗理由を操作ミスではなく配分ミスとして理解できたか
3. 再挑戦時に足場を使う順番を変えたか
4. 解けたときに「うまく操作できた」より「分かった」と感じたか

次の実装では、足場を使う順番と総消費量を考える1画面の灰箱パズルを目指す。具体的な配置は、相談してから変更する。

## 接続前に投入する長さを選ぶ実験

### 気づいた問題

接続地点までの実距離を自動で消費量にすると、消費量はプレイヤーが考えて決めた配分ではなく、振り子のルートや操作結果で決まる。通常解除を全額返却に戻すだけでは「紐を使うことに代償がない」という元の問題へ戻る。

### 今回変えたもの

- 接続前に数字キー `1` / `2` / `3` で投入長 `4` / `8` / `12` を選ぶ
- 選んだ長さを接続可能距離と振り子の半径にする
- 接続に成功した場合だけ、選んだ長さを残量から引く
- 通常解除では選んだ長さの `70%` を返し、`30%` を永久消費する
- 届かない、または照準を外して接続できなかった場合は消費しない
- 足場配置、プレイヤー操作、振り子に加える力は変更しない

### 確認すること

1. 接続前に、どの長さを使うか考えたか
2. `4` では届かず、`8` または `12` なら届く違いを理解できたか
3. 長く選ぶことの移動上の利点と、永久消費の代償が結び付いて感じられたか
4. 消費を振り子操作の結果ではなく、自分で決めた配分だと感じたか

この実験を確認するまで、新しい計画難易度型の足場配置は作らない。

## 投入長を1単位ずつ決める実験

### 3段階選択の問題

`4` / `8` / `12` の3段階では現在のステージに対して選択が粗く、必要以上に長いヒモを使わされる。プレイヤーごとの「この長さで進む」という意志を細かく反映できない。

### 今回変えたもの

- 投入長の初期値と最低値を `1` にする
- 接続していない間に、`W`を1回押すと長さを1増やす
- `S`を1回押すと長さを1減らす
- 上限は現在の残量と射出上限 `14` のうち小さい方にする
- 接続解除後も選択値を維持し、残量を超えた場合だけ自動的に下げる
- 照準線を選択した長さまで伸ばし、接続前に届く範囲を確認できるようにする
- 接続中の長さ変更と、長押しによる連続変更はまだ追加しない

### 確認すること

1. First Hookへ必要だと思う長さを、照準線を見て自分で決められたか
2. 1単位ずつ押す操作を面倒に感じなかったか
3. 最低限の長さと余裕のある長さで、振り子の利点と消費の差を感じたか
4. 接続失敗が総当たりではなく、事前の見積もり違いだと理解できたか

### 1回目の結果

- 2段目の足場へ行く場合と3段目の足場へ行く場合で、必要なヒモの長さを変えて考える動作が生まれた
- 接続する前に目的地を見て「ここならこの長さ」と判断できた
- 1単位ずつ投入長を選べる仕組みは、とてもよいと感じた
- 消費量が振り子操作の結果だけで決まらず、プレイヤーが移動前に決める計画へ変わった
- 実際に選んだ数値は今回記録していないため、次回の測定項目にする

### 足場ごとの判断内容

- 2個目の足場を目指すときは、First Hookへ届く最低限の長さを選んだ
- 3個目の足場を目指すときは、最初に2個目で使った長さをそのまま試した
- その長さでは3個目へ届かなかったため、長さ不足だと判断した
- 次の試行では投入長を増やし、3個目へ到達できた
- 同じFirst Hookを使っても、目標の足場に応じて振り子半径を変える必要があると理解できた

この結果では、最初から3個目に必要な長さを予測したのではなく、失敗結果を読んで次の投入量を修正する計画が生まれている。

### 3個目へ到達したときの予測と修正

- 2個目へ移動したときの振り子の感覚を基準に、3個目へ必要な長さを自分で予想した
- 最初の予想では3個目へ届かなかった
- 失敗後に1ずつ総当たりせず、必要量を再予想して投入長を3増やした
- 3増やした長さで3個目へ到達できた

「前の結果を読む → 必要量を予想する → 試す → 失敗から予想を修正する → 成功する」という計画難易度型の学習ループを確認できた。

### 長さ8を固定した再現性テスト

- 3個目の足場へ到達できた投入長 `8` を固定し、5回試した
- 成功は `4 / 5` 回だった
- 失敗理由として、振り子操作の難しさと足場の小ささを感じた
- 成功するために、ヒモを解除するタイミングはかなり重要だった

投入長の計画を解いた後は高い確率で再現できたため、長さの判断は有効だった。一方で実行難易度も残っている。失敗した1回は解除タイミングが悪かったと理解でき、投入長の判断ミスとは混同しなかった。原因が明確なため、現時点では足場や物理を変更せず、「計画が主、解除タイミングが副」の基準として維持する。

## 振り子を放置したときの自然減衰

### 気づいたこと

接続中の物理減衰は`0.02`だったため、入力をやめても勢いがほとんど弱まらず、放置した振り子として不自然に見えた。

### 今回変えたもの

- 接続中の`Rigidbody2D.linearDamping`を`0.02`から比較用の仮値`0.12`へ上げる
- 速度を直接減らす処理は追加しない
- 重力と`DistanceJoint2D`の張力で振り子運動を作り、Unityの物理抵抗で徐々にエネルギーを失わせる
- A/D入力は従来どおり円の接線方向へ力を加える
- 解除時は従来どおり、その瞬間の速度を保存する

### 確認すること

1. A/Dを離して見ていると、振幅と速度が少しずつ弱まるか
2. すぐ止まらず、振り子らしい往復が十分続くか
3. A/Dを再入力すると、自分で勢いを戻せるか
4. 解除した瞬間に不自然な減速や加速が起きないか

### 1回目の体感

- A/Dで力を加えたときの勢いの付き方が不自然に感じた
- 現在はキーを押している間、一定の接線方向の力`18`を毎物理フレーム加えている
- この方式は振り子を揺らす操作より、接線方向へモーターで加速する感覚になりやすい
- 数値や方式を変更する前に、押した瞬間が強いのか、押し続けると強いのか、振り子の向きと力が合わないのかを切り分ける

## A/D入力だけで一回転できる問題

### 起きたこと

- A/Dで加速できること自体はよい
- ただし、入力を続けると一回転できるほど勢いが付き、振り子として不自然だった

### 今回変えたもの

- 現在位置の高さと接線速度から、振り子の単位質量あたりの力学的エネルギーを求める
- 振り角約`80度`へ到達するエネルギーを、A/Dが追加できる上限の目安にする
- 上限の75%から接線方向の入力を滑らかに弱め、上限では追加の加速を止める
- 上限を超えていても、反対方向へ入力して減速する操作は妨げない
- 速度の直接制限や位置の強制移動は行わず、重力、`DistanceJoint2D`、物理減衰で運動を続ける

### 確認すること

1. A/Dで着地に必要な勢いを十分作れるか
2. A/Dを押し続けても一回転しないか
3. 約80度付近で、加速が急に切れたように感じないか
4. 反対方向の入力で勢いを弱められるか
5. Eを離した瞬間の飛び出しが従来どおり自然か

### 上限角度の追加調整

- 一回転は防ぎながら、もうほんの少し上まで行ける余地が欲しいと感じた
- 入力で追加できるエネルギーの上限角度を`80度`から`85度`へ上げる
- 水平になる`90度`未満に留め、入力だけで一回転できない設計は維持する
- 加速力`18`、物理減衰`0.12`、上限へ近づくと滑らかに入力を弱める方式は変えない

### 採用結果

- 上限角度`85度`でプレイし、振り子は完璧だと感じた
- 加速力`18`、最大速度目安`15`、物理減衰`0.12`、入力エネルギー上限角度`85度`を現在の基準値として採用する
- 入力による加速、放置時の自然減衰、一回転防止、高さの余裕を両立できた
- ステージや資源設計の検証で明確な問題が出るまで、振り子の物理値は変更しない
