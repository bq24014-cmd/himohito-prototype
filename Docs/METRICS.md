# ヒモヒト プロトタイプ測定基準

## 目的

今後「固定された編みポイントで紐を消費して足場を作る」実験を行ったとき、現在の振り子プロトタイプと同じ条件で比較できるようにする。

この段階ではQ2の「紐が足りなくて惜しい」を評価しない。紐の最大長 `20` は現在の操作を妨げないための仮の基準値であり、完成版の総量ではない。

## 手作業での測定方法

同じテストを5回行う。落下や明確な失敗で1回を終了し、開始地点へ戻って次を始める。

### テストA：紐を迷わず掛けられるか

- 開始位置からFirst Hookへ紐を掛ける
- 照準を決めた後、最初の `E` 入力で接続できれば成功
- 照準を合わせる時間やキー入力の回数は数えない
- `E` を押して結果を確認し、離すまでを1回の接続試行とする
- 外した場合は、照準方向・入力・見た目のどれで迷ったかを短く記録する

### テストB：Safe Landingへ着地できるか

- First Hookを使い、Safe Landingを目指す
- 着地後1秒ほど足場に残り、次の操作ができる状態なら成功
- 成功までのおおよその時間、紐を離した位置、失敗理由を記録する

### テストC：Risky Landingへ到達できるか

- First Hookを使い、3個目の足場であるRisky Landingを目指す
- 着地後1秒ほど足場に残れれば成功
- 「どのタイミングで離すかを考えたか」も記録する

### テストD：投入長を選んだ結果が分かるか

1. 開始位置で`W`を押し、照準線を見ながらFirst Hookへ届きそうな長さまで1ずつ増やす
2. 届きそうだと判断した値と、その理由を記録する
3. その値より1短い長さで接続を試し、失敗時に残量が減らないことを確認する
4. 開始状態へ戻し、判断した長さで接続・解除できるか確認する
5. さらに1長い値でも試し、振り子半径と解除後の残量の違いを記録する

確認するのは計算の正しさだけではない。「どの長さを使うかを自分で決めた」と感じたか、長く使う利点と消費の代償が結び付いていたかも記録する。

### テストE：1面を最初から最後まで通せるか

1. Start Groundから開始し、各区間で投入長を決めて進む
2. 緑色のGoalへ上から着地し、`CLEAR`が表示されるか確認する
3. `R`で位置・速度・残量が初期状態へ戻るか確認する
4. 別の試行で落下し、`FAILED`が表示されるか確認する
5. 残量1未満でも`FAILED`になり、`R`で再挑戦できるか確認する
6. クリアまでに選んだ投入長と、各選択理由を記録する

### テストF：開始残量12で資源を意識するか

1. 開始残量だけを`20`から`12`へ下げ、返却率、表示、配置、物理は変えない
2. 残量表示を自発的に見た区間を記録する
3. 次の接続に必要な長さを残すため、投入長を変えたか記録する
4. クリア時または失敗時の残量を記録する
5. 資源を考えた結果か、着地操作だけを考えた結果かを言葉で分ける

### 2026-08-09：地上最高速度の比較

- 採用値：地上最高速度 `6.5`、保持率約69.2%、踏み切り直後の横速度約 `4.5`
- 維持する値：縦のジャンプ力 `10`、空中操作、振り子物理
- 確認すること：ジャンプの高さを保ったまま、横の飛距離が扱いやすくなったか

### 2026-08-09：テストD・投入長の選択

- 2段目の足場へ行く場合と3段目の足場へ行く場合で、それぞれ必要なヒモの長さを考えた
- 接続前に目的地を見て投入長を選ぶ動作が生まれた
- 1単位ずつ長さを選ぶ方式は、とてもよいと感じた
- 消費量を振り子操作の結果ではなく、移動前の判断として扱えるようになった
- 各足場に対して実際に選んだ長さは未記録
- 次回は、選んだ長さと選択理由を足場ごとに記録する
- 2個目を目指すときは、First Hookへ届く最低限の長さを選んだ
- 3個目を目指す最初の試行では、2個目と同じ長さを選んだが届かなかった
- 長さ不足だと判断して投入長を増やした結果、3個目へ到達できた
- 失敗原因を理解し、次の試行で投入量を修正できた
- 最初の投入長は、2個目で感じた振り子の動きから予想して決めた
- 最初の予想で届かなかった後、投入長を3増やして再挑戦した
- 3増やした試行で3個目へ到達できた
- 1ずつ試す総当たりではなく、過去の振り子から予測して投入量を修正した

### 2026-08-09：投入長8で3個目への再現性テスト

### 2026-08-09：振り子の自然減衰比較

- 変更前：接続中の`Rigidbody2D.linearDamping = 0.02`
- 変更後：接続中の`Rigidbody2D.linearDamping = 0.12`
- 速度を直接変更せず、Unityの物理抵抗で運動エネルギーを徐々に失わせる
- 重力、`DistanceJoint2D`の張力、接線方向のA/D入力、解除時の速度保存は変えない
- 確認すること：入力をやめると振幅が徐々に小さくなるか、減衰が速すぎないか、A/Dで再加速できるか
- 体感：A/Dで力を加えたときの勢いの付き方が不自然に感じた
- 現在の入力処理：キーを押している間、一定の接線方向の力`18`を毎物理フレーム加える
- 次の確認：押した瞬間、押し続けたとき、振り子の向きとの関係のどこが不自然かを切り分ける

### 2026-08-10：振り子入力のエネルギー上限

- 問題：A/Dで加速し続けると、一回転できるほど勢いが付いた
- 変更：振り角約`80度`に相当する力学的エネルギーを入力加速の上限目安にする
- 上限の75%からA/Dの加速力を徐々に弱め、上限では追加の加速力を0にする
- 反対方向の入力による減速は制限せず、速度を直接上書きしない
- 重力、張力、物理減衰、解除時の速度保存は変えない
- 確認すること：A/Dで十分加速できるか、一回転しないか、上限付近で急に力が切れた感覚がないか

## 比較に使う結果

- 接続成功率：テストAの成功回数 ÷ 5
- Safe Landing成功率：テストBの成功回数 ÷ 5
- Risky Landing成功率：テストCの成功回数 ÷ 5
