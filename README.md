# ヒモヒト — Unity 2D プロトタイプ

自分の体である紐を伸ばして足場に引っかけ、振り子で進むアクションパズルの最小プロトタイプです。コードを理解しながら進められるように、機能ごとにGitコミットを分けています。

## 今回の判定対象

- 紐を振って飛ぶ操作だけで気持ちよさがあるか
- 紐の残り長さが減ると「惜しい」と感じるか
- 次にどの足場を取るか考える瞬間が生まれるか

現在の範囲は、4区間のチュートリアルと1面の本編ステージです。敵、最終アート、BGM、ヒモの切り離し、追加の本編ステージはまだ作りません。

## 起動方法

1. Unity Hubで「Add project from disk」を選び、このフォルダを指定する
2. Editorは `6000.3.21f1` を選ぶ
3. 初回コンパイル後、`Assets/Scenes/Tutorial.unity` が自動生成される
4. UnityのPlayを押す（現在開いているシーンにかかわらず`Tutorial`から始まる）
5. 操作説明を読み、キーボードの何かのキーを押して離すと開始する

自動生成されない場合は、Unity上部メニューの `HimoHito > Build Tutorial Scene` を押してください。
通しプレイ中は、Unity上部メニューの`HimoHito > Play From Tutorial`でも開始シーンを`Tutorial`へ設定できます。

## Windows版の作り方

1. Unity上部メニューの`HimoHito > Build Windows Prototype`を押す
2. `Builds/Windows/HimoHitoPrototype.exe`が作成されるまで待つ
3. `HimoHitoPrototype.exe`を起動する

Windows版には`Tutorial`と`MainStage`の2シーンがこの順番で含まれます。実行ファイルだけを移動せず、`Builds/Windows`内のデータフォルダとDLLをまとめて扱ってください。ビルド結果は再生成できて容量も大きいため、`Builds/`はGitHubへ保存しません。最終提出用のビルドと通しプレイ動画は、本編ステージ完成後に改めて作成します。

## 操作

- 開始画面では、キーボードの何かのキーを押して離す: ゲームを開始する
- `A` / `D`: 左右移動
- `Space`: ジャンプ
- `W`: 次に使う紐の長さを1増やす
- `S`: 次に使う紐の長さを1減らす
- `←` / `→`: 照準線を滑らかに回転する
- `↑` / `↓`: 照準線を真上／真下へ素早く合わせる
- `E`を押し続ける: 選んだ長さの範囲へ紐を射出し、その長さで固定する
- `E`を離す: 紐を回収し、選んだ長さの70%を戻す（残り30%は結び直すための「編み代」として消費される）
- 正常に`E`を離す: 編み糸を1個獲得する（障害物による強制解除では獲得しない）
- 編み枠の近くで`Q`: 編み糸3個を使い、指定された固定足場を編む
- `R`: 現在の区間の開始状態へ戻して再挑戦する
- マウス左ボタン: マウス照準で操作する場合の補助入力
- 緑色のゴールへ着地: `CLEAR`
- クリア画面で`Enter`: 空の本編ステージへ進む
- 落下: 「落下しました」を0.5秒表示し、現在の区間から自動で再挑戦する
- 残量が1未満: 「ヒモが尽きました」を表示し、`R`で現在の区間から再挑戦する

## コードを読む順番

### 1. `RopeResource.cs`

`currentLength` が本作の「単一の真実」です。開始残量と最大値は、チュートリアルが`12`、本編が`28`です。接続に成功すると、プレイヤーが選んだ長さを `TrySpend` します。通常解除ではその70%だけを `Refund` し、残り30%が永久消費になります。届かず接続できなかった場合は消費しません。チェックポイント後の失敗では、到達時に保存した残量へ戻ります。

HUDは数字の下に残量ゲージを表示します。ゲージは残量に応じて緑、黄、赤へ変化します。`RopeBodyVisual.cs`は同じ残量割合を読み、100%では現在の大きさ、0%では65%の大きさになるようプレイヤーの見た目だけを縮めます。ヒモを掛けている間は接続前の大きさを保ち、ヒモを外して70%の返却と30%の消費が確定した後にだけ新しい大きさへ変わります。表示専用の子オブジェクトを縮めるため、プレイヤー本体の`Transform`、`Rigidbody2D`、`Collider2D`の大きさと物理挙動は変わりません。

### 2. `RopeController.cs`

処理は次の順です。

1. `W` / `S`で投入する長さを1単位ずつ選び、矢印キーで照準方向を決める
2. 選んだ長さを上限に `Physics2D.RaycastAll` で足場を探す
3. 接続できた場合だけ、選んだ長さを `RopeResource` から消費する
4. 選んだ長さを半径として、`DistanceJoint2D` でプレイヤーと固定点を結ぶ
5. `LineRenderer` で紐を描く
6. ボタンを離すとジョイントを解除し、使った長さの70%だけを戻す。残り30%は、移動のたびに自分のヒモを結び直すための「編み代」であり、正常に外した場合は編み糸を1個得る

選択長の初期値と最低値は `1`、上限は現在の残量と射出上限 `14` のうち小さい方です。接続していない間だけ変更でき、照準線の長さも選択長と一致します。

### 3. `PlayerMover.cs`

入力は毎フレームの `Update`、物理変更は一定間隔の `FixedUpdate` で行います。足元の細い範囲が足場と重なっているかを調べて接地を判定します。`coyoteTime` と `jumpBufferTime` は、少し遅れた／早かった入力を許して操作感を良くする値です。

### 4. `PrototypeRunController.cs` / `GoalZone.cs`

開始から終了までの流れを担当します。最初はプレイヤーの物理と操作を止め、操作説明を読んでキーを離した後にゲームを開始します。緑色のゴールへ上から着地すると全画面の`TUTORIAL CLEAR`表示へ切り替わり、`Enter`で空の`MainStage`シーンへ進みます。落下時は「落下しました」を0.5秒表示し、最後に到達した区間から自動復帰します。残量1未満では「ヒモが尽きました」と表示し、`R`で現在の区間の開始状態へ戻します。プレイ中の`R`も同じ区間からの再挑戦に使います。

チュートリアルは次の4区間です。

1. 追加したTutorial Hookへヒモを掛け、Tutorial Landingへ着地する
2. Hook 1で振り、Landing 1下の障害物を避けて着地する
3. 消費したヒモから足場を編む
4. 編んだ足場を使ってゴールする

Tutorial Landing、Landing 1、編んだ足場へ着地してヒモを外すと、次の区間へ進みます。その時点のヒモ残量、選択中の長さ、編み糸、編んだ足場の状態が保存され、失敗時に復元されます。クリア後に`R`を押した場合だけ、チュートリアルの最初からやり直します。

`Assets/Scenes/MainStage.unity`は、約10区間に分けて相談しながら作る本編ステージです。現在は第10区間までを実装しています。第1区間で障害物のない`Main Hook 1`から`Main Landing 1`へ着地し、その後は徒歩区間で次の配置を観察してから、`Main Hook 2`を使って`Main Landing 2`へ進みます。第3区間は`Main Hook 3`へ掛けられる最短の長さと、`Main Landing 3`へ到達できる長さをずらし、最短がそのまま最適とは限らないことを検証します。第4〜5区間では上下に分岐し、上は難しい振り子を攻略した報酬として合流時に編み糸3個と橋を編む権利を得て、下は歩いてヒモ残量を温存する代わりに編み糸と橋の権利を得ません。上ルートは降下床、下ルートは中間床へ最初に着地した時点を中間チェックポイントとし、ヒモ残量、選択中の長さ、編み糸、橋の権利を保存します。第6区間は中間地点後の最初の難関です。短すぎるヒモでは着地点へ届かず、長すぎるヒモでは低い軌道が赤い障害物へ触れてヒモが外れます。第7区間では、上ルートを選んだ場合は編み糸3個で橋を作って歩き、下ルートを選んだ場合はヒモを使って谷を振り子で渡ります。第8区間は障害物を置かず、2つのHookと着地点を先に見せ、目の前の成功だけでなく後半へ残す量も含めた配分を検証します。第9区間では赤い横長障害物が約`8.9秒`で`y=-2.2〜7.3`を上下に往復します。低い間は振り子軌道を塞ぎ、高く上がった安全な時間を観察してからヒモを掛けます。障害物へ触れるとヒモが強制解除されますが、着地床を広めにして長さ選択や着地精度ではなくタイミング予測を検証します。第10区間は新しい難しさを置かず、1つの高いHookから右下の横幅`36`の緑色ゴールへ大きく飛ぶ締めの区間です。ゴールは元の左端を維持し、右側だけを広げています。ゴールへ着地すると全画面の`MAIN STAGE CLEAR`を表示します。現在は制作中区間から直接始める設定を無効化しており、`Tutorial`クリア後に`Enter`を押すと本編第1区間から開始します。本編の開始残量は確定値`28`で、第8区間を含め、途中で別の値へ上書きせずゴールまで引き継ぎます。チェックポイントでは到達時の残量を保存し、失敗時に同じ値へ戻します。上ルートでは`8.5`、下ルートでは`10.0`を残してクリアできた通し結果を基に、この総量を採用しています。開始時は現在作られている範囲の終端側から現在の区間へ見せます。チュートリアルは明示的な指示があるまで変更しません。

## 振り子の物理

- 地上では目標速度へ近づけ、キーを離したときは加速より強い減速で滑りを短くする
- 地上の最高速度は `6.5` とし、移動の速さと着地時の扱いやすさを両立する
- 地上からジャンプするときは横速度を約69.2%残し、最高速からの踏み切りを約 `6.5` から約 `4.5` に抑える
- 空中では速度を直接書き換えず、弱い横方向の力だけを加える
- 紐の接続中は `DistanceJoint2D` が張力を担当する
- `D`は反時計回り、`A`は時計回りの接線方向へ力を加え、振り子を少しずつ加速する
- A/Dが加えるエネルギーは振り角約`85度`を上限の目安に徐々に弱まり、入力だけで一回転できないようにする
- 入力を離しても速度は直接消さず、`Rigidbody2D.linearDamping = 0.12`の物理抵抗で徐々に勢いを弱める
- `E`を離した瞬間の速度を保存し、そのまま放物運動へ移る
- プレイヤーの接触摩擦は0.1に抑え、足場で滑りすぎず、角でも空中移動が止まらないようにする
- カメラは第1〜9区間では高さを固定して横移動だけを追従し、第10区間ではプレイヤーが画面中央に近づくよう縦方向も滑らかに追従する
- 本編開始時の確認カメラは、通常の画角`8.7`より少し引いた`11.5`でゴールの高さを基準に映し、開始地点へ戻る間に通常画角へ近づく。移動速度は毎秒`30`座標とし、縦横を合わせた距離に応じて移動時間を延ばす

HUDの `SPEED` を見ると、振り子の最下点で速くなり、端で遅くなることを確認できます。

### 5. `PrototypeSceneBuilder.cs`

横長のステージに、安全なTutorial HookとTutorial Landing、長さ選択を試す縦長障害物、上側の計画ルート、編む場所、緑色のゴール、4区間のチェックポイント、横方向だけの追従カメラを自動配置するEditor専用コードです。最初の区間では追加したHookへの接続を安全に覚え、次の区間ではHook 1の長い振り子が障害物へ触れるかを比較します。その後、消費したヒモから足場を編み、最後にゴールへ渡ります。ゲーム中の挙動ではなく「検証環境を再現するコード」なので、最後に読めば十分です。

### 6. `RopeReleaseHazard.cs`

赤い縦長障害物への接触を検知するチュートリアル用コードです。障害物がヒモを外すのは、第2区間で2個目の着地点へ向かっている間だけです。有効な区間で接触すると`RopeController.DetachAndRefund`を呼び、振り子の勢いを残したまま落下して失敗になります。2個目の着地点へ到達して第3区間へ進むと、赤い表示と当たり判定を無効化します。第3区間からの再挑戦では消えた状態を保ち、チュートリアルを最初から再開した場合だけ再表示します。

### 7. `WeaveResource.cs` / `WeaveFrame.cs`

プレイヤーが自分でヒモを解除すると、`WeaveResource`へ編み糸が1個加わります。紫色の編み枠へ近づくと、プレイヤーの頭上に「編む場所」、現在数／必要数、`Q`で編めるか／あと何個必要かをまとめて表示します。編み糸が3個ある状態で`Q`を押すと、決められた位置に固定足場が完成します。Tutorial Hook、Hook 1、Hook 2で得た3個を使い、それまでの移動が足場へ変わる構成です。赤い障害物による強制解除では編み糸を獲得しません。

## Gitで差分を学ぶ

```powershell
git log --oneline
git show 26f55f7
git diff 26f55f7 26873c8
```

- `git show 26f55f7`: 移動だけを追加したコミットを見る
- `git diff 26f55f7 26873c8`: 移動だけの状態から紐機能がどう増えたかを見る

実験するときはmainを直接変えず、次のようにブランチを作ります。

```powershell
git switch -c experiment/rope-feel
```

たとえば重力、移動速度、紐の最大長を変え、1項目ずつコミットすると比較しやすくなります。

## GitHub Desktopで公開する

1. GitHub Desktopの `File > Add local repository` を選ぶ
2. この `HimoHitoPrototype` フォルダを指定する
3. `Publish repository` を押す
4. Repository nameを `himohito-prototype` にする
5. 学習中は `Keep this code private` を有効にしてもよい

すでにローカルGit履歴があるため、公開後も機能ごとのコミットがそのまま表示されます。
