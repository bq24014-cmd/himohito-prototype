# ヒモヒト — Unity 2Dアクションパズル

自分の体であるヒモを伸ばして足場に掛け、振り子の勢いで進む2Dアクションパズルです。

ヒモは移動手段であると同時に、ステージ全体で管理する有限の資源です。プレイヤーは「どこへ掛けるか」だけでなく、「次の移動にどれだけの長さを使うか」を自分で決めます。

## プロトタイプの目的

このプロトタイプでは、次の3点を検証しています。

- 自分の体を使って振り子で飛ぶ操作に爽快感があるか
- ヒモの長さを自分で選ぶことで、移動前に考える時間が生まれるか
- 限られた残量を使いながら進むことで、成功時の達成感や失敗時の「惜しい」が生まれるか

現在の内容は、4区間のチュートリアルと、9区間で構成された本編ステージ1面です。障害物エリアは夜の子供部屋を表す円形の懐中電灯の光で統一しています。接続中のプレイヤーが光に触れるとヒモが強制的に外れますが、そのヒモは全回収されます。チュートリアルの光は固定され、第6区間は横、第8区間は縦に動きます。第6区間は1往復後、徐々に消えてから徐々に点くまでの3秒間が安全に通れる時間になります。

## 世界観方針と現在の状態

舞台は、子供が眠った後の夜の子供部屋です。積み木、プラレール、絵本、毛糸玉などが地形になり、編みかけのまま忘れられた、ほどけかけのあみぐるみが、おもちゃ箱を目指します。丸い毛糸の頭、小さな身体、頭上の接続糸、下側の3本のほどけた糸で「自分の身体がヒモである」ことを見せます。プレイヤーが小さくなるほど家具が大きく見え、世界の巨大さが際立つ構成を目指しています。

現在はゲーム性を確認するグレーボックス段階です。夜の暗さ、懐中電灯、自分の身体であるヒモ、残量に応じた身体の縮小は実装済みです。プレイヤー表示には桃色の毛糸で編まれたあみぐるみを採用し、地上移動中は8コマの歩行アニメーションを再生します。停止、空中、ヒモ接続中は立ち姿へ戻り、当たり判定と物理サイズは従来のまま保っています。チュートリアルには、夜の子供部屋の正式な背景方針として、月明かりの窓、玩具棚、積み木、絵本、レール、毛糸玉を描いた背景を採用しています。チュートリアルの背景はカメラ移動の90%、長い本編では97%だけ横へ追従させ、画像の端が見えない範囲で視差を残しています。両方のステージでプレイヤーとヒモは桃色、接続前の照準線は区別できる薄桃色、開始床は橙色の積み木、着地床は青い玩具レール、Hookは青い玩具コネクターとして表示します。チュートリアルの最後はふたが開いたおもちゃ箱、本編の広いゴールは青い玩具レールとその進入側に置いたおもちゃ箱で表現します。Hookへ接続できた時は短い玩具コネクター音、プレイヤーがヒモを離して飛ぶ時は速度に応じた風切り音が鳴ります。

## ゲームの特徴

### ヒモの長さを自分で決める

ヒモを掛ける前に、使用する長さを1単位ずつ選びます。短いヒモはHookへ届かなかったり、振り子の軌道が窮屈になったりします。長いヒモは遠くへ掛けやすい一方、振り子の軌道が低くなり、障害物へ触れやすくなる場合があります。

そのため、常に最短または最長を選べばよいのではなく、Hook、着地点、障害物の位置を見て長さを判断します。

### 自分の体を消費して進む

ヒモを掛けると、選んだ長さが残量から一時的に使われます。接続中にもう一度`E`を押して移動を終える場合は、その全量を回収します。通常の振り子移動では残量を失わず、`Q`でヒモを足場に変えた時だけ、足場になった実距離を永久に消費します。

これにより、操作ミスではなく「ここに自分のヒモを残して道を作る」というプレイヤー自身の判断が消費になります。

プレイヤーと接続中のヒモには同じ色を使い、ヒモが道具ではなく自分の身体であることを示します。残量は数字とゲージに加え、プレイヤーの見た目が小さくなり、接続中のヒモが細くなることでも表現します。見た目だけを変化させ、当たり判定や物理挙動は変えないため、残量によって操作感が不公平にならないようにしています。

### 引いたヒモをその場で足場にする

Hookへ掛けたまま`Q`を押すと、Hookから現在のプレイヤー位置までのヒモが、その長さの歩ける足場として残ります。使う量と作る位置は固定されておらず、プレイヤーが振り子で到達した場所によって決まります。

足場になった実距離は残量から永久に消費されます。残量をすべて使い切る足場は作れません。移動に使った自分の身体がその場に道として残ることで、「自分を使って進み、その痕跡を編む」という本作のテーマを操作へ直接つなげています。

斜めの足場を作った場合は、入力を止めるとその場で踏みとどまります。生成直後や足場の端で接地判定が一瞬途切れても、短い接触猶予によって滑り止めが継続します。`A` / `D`を入力している間は通常どおり坂を歩けるため、自由な角度で作った足場を移動に使えます。

### 計画と操作の両方を試すステージ

本編では、ヒモの長さを考える区間、振り子を離すタイミングを試す区間、障害物の動きを観察する区間を分けています。終盤は新しい難しさを増やさず、大きく振ってゴールへ飛ぶ爽快感を中心にしています。

## ゲーム構成

### チュートリアル

1. ヒモをHookへ掛け、振り子で着地する
2. 振り子中のプレイヤーが懐中電灯の光へ触れると、ヒモが外れることを体験する
3. 接続中のヒモを、好きな位置で足場にする
4. 作った足場の先から2個目のHookへ掛け、振り子でゴールする

各区間の着地点がチェックポイントです。落下した場合は、到達時点のヒモ残量、選択中の長さ、作った足場の状態から再開します。第3区間では途中の固定床を置かず、足場を作らないと2個目のHookへ届きません。足場を作った瞬間に第4区間へ進み、その足場を残した状態から再挑戦できます。

### 本編ステージ

- 第1〜3区間：基本操作と、Hookへ届く最短値が移動の最適値とは限らないことを確認する
- 第4〜5区間：前半を終えた後の広い一枚床で立ち止まり、中間チェックポイントから後半を見渡す
- 第6区間：横に動く懐中電灯と、徐々に暗くなって戻る3秒間を観察し、渡るタイミングを選ぶ
- 第7区間：最初のヒモを任意の位置で足場に変え、その先から次のHookへヒモを掛けて谷を渡る
- 第8区間：上下する懐中電灯の光を観察し、ヒモが照らされない時間を選んで進む
- 第9区間：1つのHookで大きく振り、ゴールへ飛ぶ

本編の開始残量は暫定で`28`です。通常解除を全回収へ変更したため、以前の70%返却を前提にした上ルート`8.5`、下ルート`10.0`という結果は現在のバランス判定には使用しません。自由な足場化を通して試した後、開始残量を改めて調整します。

## 操作

| 入力 | 操作 |
| --- | --- |
| `A` / `D` | 左右移動／接続中に振り子を加速 |
| `Space` | ジャンプ |
| `W` / `S` | 次に使うヒモを1単位ずつ増減（長押しで連続変更） |
| `←` / `→` | 照準を滑らかに回転 |
| `↑` / `↓` | 照準を真上／真下へ合わせる |
| 未接続時に`E` | 選んだ長さでヒモを掛ける |
| 接続中に`E` | 勢いを保ったままヒモを外し、使った長さを全回収する |
| ヒモ接続中に`Q` | Hookから現在位置までのヒモを、その場に歩ける足場として残す |
| `R` | 現在の区間から再挑戦 |
| マウス左ボタン | マウス照準を使う場合の補助入力 |

開始画面では、操作説明を読んだ後に任意のキーを押して離すとゲームが始まります。チュートリアルをクリアした後は`Enter`で本編へ進みます。本編クリア後は`R`で第1区間から再挑戦できます。

## 使用素材とライセンス

- Hook接続音：Kenney「Impact Sounds 1.0」の`impactWood_light_002.ogg`と`impactSoft_medium_000.ogg`を使用
- ライセンス：Creative Commons Zero（CC0 1.0）
- 配布元：[Kenney — Impact Sounds](https://kenney.nl/assets/impact-sounds)
- 同梱ライセンス：`Assets/ThirdParty/KenneyImpactSounds/License.txt`
- ヒモ解除時の空気音：プロジェクト用に作成した短いノイズ音を使用（外部素材なし）

接続音は木製玩具が軽く触れる音を中心にし、毛糸の柔らかさを表す音を小さく重ねています。接続に成功した時だけ鳴り、接続できなかった入力では鳴りません。解除音は夜の静けさを壊さない短い「スッ」という空気音です。プレイヤーが`E`またはマウス入力で自分からヒモを離した時だけ鳴り、離した瞬間の速度が大きいほど聞こえやすくなります。速度`4`以下では鳴らず、高速でも約`0.1`秒で消えるようにして、着地音と誤解しないようにしています。障害物による強制解除、落下、再挑戦では鳴りません。着地は不自然な衝撃音を足さず、毛糸の身体が短く潰れて戻る見た目で伝えます。当たり判定と物理サイズは変化しません。

## 起動方法

### Unity Editorで実行

1. Unity Hubで「Add project from disk」を選び、このフォルダを指定する
2. Unity `6000.3.21f1`でプロジェクトを開く
3. UnityのPlayを押す
4. `Tutorial`からチュートリアル、本編の順にプレイする

シーンを再構築する場合は、Unity上部メニューの`HimoHito > Build Tutorial Scene`を使用します。現在開いているシーンにかかわらず通しプレイを始める場合は、`HimoHito > Play From Tutorial`を使用します。

現在は後半確認期間の開発用設定として、通常のPlayを押した直後から`MainStage`の中間チェックポイントで始まります。落下や`R`でも同じ中間地点へ戻ります。通し確認へ戻る際は、Play開始シーンと中間開始の一時設定を解除します。手動で通しプレイへ切り替える場合は、Unity上部メニューの`HimoHito > Play From Tutorial`を使用します。

### Windows版を作成

1. Unity上部メニューの`HimoHito > Build Windows Prototype`を押す
2. `Builds/Windows/HimoHitoPrototype.exe`が作成されるまで待つ
3. `Builds/Windows`内のデータフォルダとDLLを含めた一式を同じ場所に置いて起動する

ビルド結果は再生成でき、容量も大きいため、このリポジトリには含めていません。

## 技術設計

- Unity 2DとBuilt-in Input Managerを使用
- `DistanceJoint2D`でヒモの張力を表現
- 空中と接続中は速度を直接上書きせず、力を加えて移動
- ヒモを外した瞬間の速度を保ち、振り子の勢いを次の移動へ引き継ぐ
- 接続中の入力は、Hookを中心とする円の接線方向へ加える
- 入力によるエネルギーには上限を設け、加速だけで一回転できないようにする
- 弱い物理抵抗で、入力を止めた振り子の勢いが少しずつ減衰する
- ヒモ残量は`RopeResource.currentLength`だけで管理し、HUD、ゲージ、見た目、射出上限を同じ値から派生させる
- チェックポイントでは全回復せず、到達時点の資源状態を保存・復元する

主要なコードは次の役割に分けています。

| ファイル | 役割 |
| --- | --- |
| `Assets/Scripts/RopeResource.cs` | ヒモ残量の消費・返却・復元 |
| `Assets/Scripts/RopeController.cs` | 照準、接続判定、ヒモの描画、解除 |
| `Assets/Scripts/PlayerMover.cs` | 地上・空中・振り子中の移動 |
| `Assets/Scripts/PrototypeRunController.cs` | チュートリアルの開始・失敗・クリア |
| `Assets/Scripts/MainStageRespawnOnFall.cs` | 本編のチェックポイントと再挑戦 |
| `Assets/Scripts/RopePlatformBuilder.cs` | 接続中のヒモの足場化、生成した足場の保存・復元 |
| `Assets/Scripts/HorizontalCameraFollow.cs` | 横追従と最終区間の縦追従 |
| `Assets/Scripts/TutorialBackgroundParallax.cs` | チュートリアル背景をカメラへ緩やかに横追従 |

## 今後の拡張

このプロトタイプでは、ヒモを使った振り子移動と、有限の長さを配分する判断を優先しました。次の要素は構想にありますが、コア体験の評価を曖昧にしないため、現段階では実装範囲から外しています。

- **素材変化**：ゴムや鋼線などで伸縮性や重さを変える案。現在の物理と長さ選択の評価を終えてから、素材ごとの役割を設計する
- **足場化の難易度調整**：自由配置は実装済み。第三者テストで、必要量、作りやすい位置、想定外の近道が計画の面白さにつながるかを確認する
- **敵**：ハサミや火など、ヒモそのものを狙う存在。現在の懐中電灯は敵キャラクターではなく、軌道や開始タイミングを考えるための固定・往復ギミックとしている
- **物理的なたるみ**：現在は物理を変えず、選んだ長さと実距離の差を描画のたるみとして見せている。複数関節による物理的なたるみは操作感を大きく変えるため、別の検証段階で扱う
- **アート・演出・音**：チュートリアル全体の背景・玩具表示、Hook接続音、速度に応じた解除音、毛糸の着地演出を縦に試作している。本編ステージの見た目は比較後に展開する
- **追加ステージ**：本編1面の通し体験と資源バランスを優先し、新しい面は現在の仕組みを第三者テストで評価した後に検討する
